# PRD 시각 자료

Project Librarian은 복잡한 PRD 시각 자료를 독립적인 HTML 산출물로 취급합니다. Markdown는 메타데이터, 요구사항, 근거, 결정사항, 텍스트 요약을 보존하는 경로로 사용하고, HTML은 시각적 표현의 원본으로 사용합니다.

## 지원하는 시각 자료

| 시각 자료 | 일반적인 PRD 영역 | 답해야 하는 질문 |
| --- | --- | --- |
| 사용자 여정 지도 | `01-discovery` | 전체 여정에서 사용자는 어떤 경험을 하는가? |
| 생태계·이해관계자 지도 | `01-discovery` | 문제를 둘러싼 사람, 시스템, 이해관계자는 누구인가? |
| 사용자 플로우 | `02-requirements` | 어떤 경로, 분기, 완료·이탈 지점이 존재하는가? |
| 서비스 블루프린트·스윔레인 | `02-requirements` 또는 `06-operations` | 사용자 접점과 내부 단계의 소유자는 누구인가? |
| 권한 매트릭스 | `02-requirements` | 역할별로 어떤 기능을 조회·변경할 수 있는가? |
| 시스템 컨텍스트·아키텍처 | `03-design` | 시스템 경계, 구성요소, 데이터 흐름은 무엇인가? |
| 시퀀스 다이어그램 | `03-design` | 액터·서비스·이벤트 사이에서 시간 순서대로 무엇이 일어나는가? |
| 상태 머신 | `03-design` | 어떤 상태, 전이, 조건, 복구 경로가 존재하는가? |
| 화면 플로우·와이어프레임 | `03-design` | 사용자는 무엇을 보고 화면은 어떻게 연결되는가? |
| 도메인·데이터 모델 | `03-design` | 중요한 엔티티, 관계, 소유권, 생명주기는 무엇인가? |
| 의존성·롤아웃 맵 | `04-delivery` 또는 `08-roadmap` | 무엇이 먼저 필요하며 변경을 어떻게 안전하게 출시하는가? |
| 실험 흐름·퍼널 | `05-validation` 또는 `07-metrics` | 어느 단계에서 전환·실패하며 변형별 차이는 무엇인가? |
| KPI 트리·코호트 뷰 | `07-metrics` | 결과 지표는 어떻게 분해되고 시간·집단별로 어떻게 변하는가? |
| 결정 영향도 맵 | `09-decisions` | 결정이 어떤 제품·기술·팀 영역에 영향을 주는가? |
| 근거 맵 | `10-sources` | 어떤 조사와 출처가 주장이나 결정을 뒷받침하는가? |

이 목록은 시작용 네 가지로 제한된 목록이 아닙니다. PRD 이해에 실질적으로 도움이 되는 유형은 모두 사용할 수 있으며, 내용이 없는 시각 자료를 형식적으로 만들지는 않습니다.

## 저장 위치와 라우팅

HTML 파일은 서비스, PRD, 문서 영역을 소유하는 경로 아래에 둡니다.

```text
wiki/10-services/<service>/prds/<PRD-ID-slug>/03-design/
  index.md
  visuals/
    system-architecture.html
    state-machine.html
```

탐색, 요구사항, 검증, 운영, 지표, 로드맵, 결정, 출처에 속한 자료는 각각 해당 영역에 두고 모든 시각 자료를 `03-design/`에 몰아넣지 않습니다. 각 HTML은 영역의 `index.md` 또는 집중된 Markdown 문서에서 연결합니다. `checkout-user-flow.html`, `payment-rollout-map.html`처럼 안정적이고 의미가 분명한 이름을 사용합니다.

## HTML 작성 계약

모든 표준 PRD 시각 자료는 다음을 만족해야 합니다.

- 의미 있는 `<title>`과 제목을 가진 자체 완결형 `.html` 파일이어야 합니다.
- 목적, 범위, 소유자, 갱신일을 표시해야 합니다.
- 텍스트 요약 또는 동등한 접근성 표현을 포함해야 합니다.
- 기호, 색, 선 모양이 의미를 가지면 범례를 제공해야 합니다.
- 반응형·인쇄 가능하고 키보드로 탐색할 수 있어야 하며 색상만으로 의미를 전달하지 않아야 합니다.
- 외부 CDN 대신 인라인 CSS/SVG 또는 저장소 내부 자산을 사용해야 합니다.
- 관련 요구사항, 결정사항, 출처 근거를 안정적인 상대 경로로 연결해야 합니다.
- 해석에 영향을 주는 현재/미래 경계와 미해결 가정을 표시해야 합니다.

Markdown 경로는 프런트매터, 근거, 수용 기준, 결정사항, 출처 요약의 원본으로 유지합니다. 제품 동작이 바뀌면 Markdown 경로와 HTML 시각 자료를 같은 변경에서 함께 갱신합니다. 작은 설명에는 Mermaid나 ASCII를 사용할 수 있지만, 지원하는 PRD 시각 자료의 표준 산출물은 HTML입니다.

## 검토 체크리스트

시각 자료를 완료하기 전에 다음을 확인합니다.

1. 단순한 문장이나 작은 표보다 시각 자료가 더 분명하게 답하는 PRD 질문이 있는가?
2. 모든 노드, 액터, 상태, 전이, 의존성에 모호하지 않은 라벨이 있는가?
3. 연결된 요구사항·결정 문서와 내용이 일치하는가?
4. HTML을 렌더링하지 않아도 텍스트 요약만으로 핵심 결론을 이해할 수 있는가?
5. 링크, 참조, 검토 조건이 여전히 유효한가?
